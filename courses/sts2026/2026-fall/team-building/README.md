# STS2026 프로젝트 팀빌딩

공개 주소: https://haicolab.sogang.ac.kr/courses/sts2026/2026-fall/team-building/

## 교수자 첫 운영

1. Supabase 프로젝트에서 Authentication → Sign In / Providers → User Signups의 **Confirm email을 끈다**. 이메일 로그인과 신규 가입은 켠다. 사이트는 학번별 비공개 초대코드로 가입 자격을 확인한다.
2. 새 프로젝트의 SQL Editor에서 `setup.sql`을 **한 번만** 실행한다. 마지막 결과의 `professor_invite_code`를 보관한다. 이 코드를 공개하지 않는다.
3. `config.js`에 프로젝트 API URL과 publishable key를 설정한다. service_role/secret key는 넣지 않는다.
4. 사이트의 처음 가입하기에서 학번 `professor`, 위 코드, 교수자 이메일, 새 비밀번호를 입력한다.
5. 교수자 관리 → 수강생 명단 등록에 학번들을 붙여 넣는다. 내려받은 CSV에는 개인별 초대코드가 들어 있다. **CSV 전체를 공개하지 말고 각 학생에게 자기 코드만 LMS로 전달**한다.
6. 학생들은 본인 학번·개인 코드·이메일·비밀번호로 가입한다. 번호 ID는 가입 때 발급되고 유지된다. 교수자는 학생 번호를 소비하지 않는다.
7. 교수자 관리에서 공지와 제출·모집 허용 여부를 설정한다. 마감하려면 두 허용 항목을 모두 끈다.
8. 최종 명단 CSV를 내려받아 팀 구성과 미제출·미소속 학생을 확인한다.

초대 CSV를 잃어버렸다면 미가입 학생 행의 ‘초대 재발급’을 사용한다. 기존 코드는 무효화된다. 가입한 학생은 코드를 다시 사용할 필요가 없다.

## 학생 안내문

> 생성형 AI의 이해와 활용 프로젝트 팀빌딩을 시작합니다.
>
> 접속: https://haicolab.sogang.ac.kr/courses/sts2026/2026-fall/team-building/
>
> 1. 개별 전달받은 초대코드와 학번으로 가입하세요. 이후에는 가입한 이메일과 비밀번호로 로그인합니다.
> 2. 아이디어를 제안하세요. 문제 상황, 설명 이미지 1장, 기대 결과, 데이터 구상, 필요한 기술, 기여 역량, 원하는 팀원을 적어 주세요.
> 3. 이미 팀이 있으면 팀장이 대표로 제출하고, ‘내 활동’에서 기존 팀원의 학번을 등록합니다. 팀원은 자기 계정에서 소속을 확인하세요.
> 4. 관심 있는 아이디어에 익명 댓글이나 비공개 합류 지원을 보내세요. 팀장이 합류를 제안하고 지원자가 수락하면 팀원으로 확정됩니다.
> 5. 팀은 팀장 포함 최대 3명이며, 1인·2인팀으로 진행해도 됩니다. 게시자는 해당 아이디어의 고정 팀장입니다.
>
> 이름·학번·연락처를 본문, 댓글, 이미지에 적지 마세요. 교수자만 학번과 번호 ID의 대응을 확인합니다.
> 최신 지원과 팀 구성은 상단 ↻ 버튼으로 갱신할 수 있습니다.

## 비밀번호와 이메일

기본 설정은 가입·로그인에 메일 발송을 요구하지 않는다. 학생은 이메일을 정확하게 입력하고 비밀번호를 보관해야 한다.

Supabase 기본 메일 발송은 수신자·발송량 제한이 있으므로 이메일 재설정 버튼은 기본적으로 숨긴다. 메일 재설정을 사용하려면 Custom SMTP를 연결하고 Auth URL Configuration의 Site URL/Redirect URLs에 실제 팀빌딩 URL을 추가한 뒤 `config.js`의 `emailRecoveryEnabled`를 `true`로 설정한다. 실제 수강생 이메일로 재설정을 검증한 후 사용한다.

SMTP 준비 전 비밀번호를 잊은 학생은 교수자에게 요청한다. 교수자는 저장소의 `scripts/team-building/reset-password.mjs`를 로컬에서 실행해 Supabase 공식 Admin API로 비밀번호를 재설정할 수 있다. 서비스 비밀키는 이 로컬 명령에만 입력하며, 학생·사이트·Git 저장소·채팅으로 전달하지 않는다. 학생에게 임시 비밀번호를 개별 전달한 후 ‘내 활동 → 비밀번호 변경’에서 바꾸게 한다.

```sh
node scripts/team-building/reset-password.mjs
```

## 데이터와 권한

- `team_private` 스키마에 학번, 초대 해시, 게시글, 팀 구성, 지원 내역을 저장한다. 브라우저 역할은 테이블에 직접 접근할 수 없다.
- 두 RPC가 로그인과 서버의 역할 정보를 검사한다. 학생용 응답에는 다른 학생의 학번, 이메일, 초대코드가 포함되지 않는다.
- 최초 가입 권한은 사전 명단과 학번별 일회용 코드로 검증한다. 사용자가 임의로 수정할 수 있는 메타데이터를 관리자 권한 판단에 사용하지 않는다.
- 팀원 수, 예약된 기존 팀원 자리, 중복 소속은 데이터베이스 트랜잭션 안에서 검사한다.
- 이미지는 비공개 Storage 버킷에 저장한다. 인증된 수강생과 교수자에게만 읽기 권한이 있으며 화면에는 만료되는 서명 URL을 사용한다. 다운로드한 이미지나 캡처를 통한 공유까지 막는 기능은 아니다.
- 브라우저 업로드 시 최대 1600px WebP로 다시 인코딩한다. 원본 파일명과 EXIF를 업로드하지 않는다.
- 개인정보를 GitHub에 저장하지 않는다. 관리자 CSV는 내려받은 교수자의 기기에서 관리한다.
- 수업 종료 후 사이트 활동을 닫고, 필요한 최종 명단을 내보낸 후 개인정보 보관·삭제 시점을 정한다.

## 구현 범위

아이디어 작성/수정, 설명 이미지, 검색/필터, 익명 댓글과 삭제, 비공개 지원과 팀장 답변, 합류 제안과 수락, 기존 팀원 확인, 교수자 수강 명단·초대 발급·CSV·마감·소속 정정을 제공한다. 모바일을 지원한다.

초기 버전에는 실시간 채팅, 이메일 알림, 자동 매칭, 서버 임시 저장이 없다. 글 작성 중 새로고침하면 미저장 입력이 사라지므로 긴 글은 따로 보관한 뒤 제출하는 것을 권장한다. ‘모집 종료’ 상태에서도 기존 팀원 확인 요청은 가능하다. 팀 확정은 현재 소속 확인된 구성원을 기준으로 교수자가 명단에서 최종 확인한다.

## 검증과 로컬 개발

```sh
npm ci --prefix scripts/team-building
node scripts/team-building/database.test.mjs
python3 -m http.server 8765 --bind 127.0.0.1
# 다른 터미널
node scripts/team-building/browser.test.mjs
```

데이터베이스 테스트는 PGlite의 실제 PostgreSQL 엔진에 Supabase auth/storage 최소 스키마를 구성한 뒤 배포 SQL 그대로 실행한다. 브라우저 테스트는 동일한 SQL을 API 응답에 연결한다. 이는 실제 Supabase Auth/Storage 운영 연결 테스트와는 구분된다. 공개 배포 후 실제 계정 가입과 이미지 업로드 확인을 추가로 진행한다.

예시 화면: URL 뒤에 `?demo=1`. 예시 데이터는 브라우저 내부에서만 생성되며 실제 DB에 저장되지 않는다.

Supabase JS 클라이언트는 버전을 고정해 로컬 번들로 포함한다. 재생성:

```sh
scripts/team-building/node_modules/.bin/esbuild scripts/team-building/node_modules/@supabase/supabase-js/dist/index.mjs --bundle --format=esm --minify --outfile=courses/sts2026/2026-fall/team-building/vendor/supabase.js
```

기존 루트 `CNAME`을 보존한다. GitHub Pages는 `main` 루트에서 배포한다.
